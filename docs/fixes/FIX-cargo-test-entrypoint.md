# Fix Ledger: cargo-test-entrypoint

- **Status:** FIXED
- **Symptom:** `cargo test --manifest-path src-tauri/Cargo.toml` compiles successfully, then `launchify_lib-*.exe` exits with `0xc0000139` (`STATUS_ENTRYPOINT_NOT_FOUND`).
- **Expected:** `cargo test --manifest-path src-tauri/Cargo.toml` runs all unit tests and passes.
- **Trigger:** Running `cargo test` on Windows.
- **Environment:** Windows, Tauri v2, `launchify` (`src-tauri`).

## Hypotheses
1. **H1 (Leading):** `WebView2Loader.dll` is missing from `src-tauri/target/debug/deps/` (where `cargo test` places test executables) or an incompatible `WebView2Loader.dll` is being loaded from `PATH` / `System32`, causing `STATUS_ENTRYPOINT_NOT_FOUND`.
2. **H2:** Another DLL dependency in `target/debug/deps` is missing or mismatched.

## Attempts
1. **Fix:** Linked `libresource.a` (generated by `tauri-build`, containing the Common Controls v6 manifest) into test binaries via `cargo:rustc-link-arg-tests` in `src-tauri/build.rs`.
   - **Result:** `launchify_lib` unit test binary now launches and executes all 49 tests (`44 passed; 5 failed`). The `0xc0000139` (`STATUS_ENTRYPOINT_NOT_FOUND`) loader error is resolved.
